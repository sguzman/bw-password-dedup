# Security and resilience assessment — in progress

**Scope:** Review of the Rust CLI and its Linux synthetic acceptance fixtures through the 2026-11-02 development checkpoint. This is a concrete engineering audit log, **not** an independent security audit, a certification, or permission to import live credentials. M7-03 remains unverified until the remaining risks are assessed and tested.

## Verified controls and their evidence

| Control | Implementation or evidence | Residual limitation |
| --- | --- | --- |
| Detect changes to original exports | The shared `src/source_io.rs` reader opens with Linux `O_NOFOLLOW`/`O_NONBLOCK`, preventing final-component symlink and FIFO swaps from being followed or blocking before `fstat`; it verifies descriptor/path identity, size and timestamps before/after bounded reads. Synthetic pre-open symlink/FIFO swaps, in-place growth and pathname replacement tests passed. | Checks detect common races but do **not** provide an atomic snapshot against hostile same-user writers or unsafe parent-directory swaps. Use a private, quiescent copy. |
| Destination ancestry safety | `src/path_safety.rs` rejects other-user-writable output parents, unsafe writable ancestors and symlinked directory components before export or review-key initialization; the writer rechecks before publishing. A trusted sticky-bit ancestor is permitted only above a non-shared-writable output directory. | No pathname preflight can defend against malicious concurrent writes by a process with the same account, or guarantee filesystem atomicity. Operate in a private, quiescent directory. |
| Refuse accidental overwrites | Existing outputs fail by default; new outputs use private temporary files and hard-link no-clobber installation. When a late error follows a successful hard link, cleanup checks the staged file's device/inode before removing the newly linked output; a synthetic post-publication failure regression passes. | This does not make multiple files a crash-atomic transaction; kill/power loss and a hostile directory writer still require inspection. |
| Explicit force-replacement recovery | Writer isolated in `src/private_write.rs`. Before replacing a forced output, the old file is opened with `O_NOFOLLOW`/`O_NONBLOCK`, copied to a private mode-0600 backup, and its inode, byte count, size, mtime and ctime are verified before and after copying, including pathname identity. Mutation and pre-open symlink substitution tests passed. | A hostile same-user writer can still race the final check and rename; a forced replacement after uncertain durability keeps the backup for inspection. Multiple output files remain nontransactional. |
| Companion-output rollback and final verification | `src/bundle.rs` publishes companions before the primary JSON, then checks each published file's private permissions, device/inode, size, mtime/ctime, and streamed SHA-256 against the original bytes, **twice**: immediately after writing and again for the whole bundle before success. On ordinary verification failures it attempts inode-checked cleanup of new outputs. Synthetic corrupt-content, late companion alteration, and permission-change regressions passed. | Cross-file crashes, kill/power loss, same-user races, failed unlink, and uncertain forced primary replacement can still leave partial files; verify all destinations and retained backups before import. |
| Durable incomplete-export marker | Before publishing any output, `src/bundle.rs` creates and syncs a private `.<primary-filename>.bw-dedup.incomplete` marker in the primary's directory. It lists expected destinations, contains no secret values, and is removed with a directory sync only after the publisher verifies the full bundle. Existing markers block a new run, including `--force`. Synthetic interruption, stale-marker rejection, success removal and collision tests pass. | The marker is a recovery warning, not a commit certificate or atomic transaction. Other processes could delete it; a late fsync failure and power loss may still yield uncertain state. Pathnames are metadata that require privacy. |
| Redacted reports | Synthetic canary tests confirm usernames, domains, passwords and TOTP seeds do not appear in report data | A local file path in stderr or shell history can still reveal contextual information |
| Correct secret matching | Password and TOTP values require exact equality, including capitalization; unsafe legacy `--keep` modes fail closed | Source CSVs may omit passkeys, external authenticators or other attributes |
| Authenticated conflict replay | HMAC-SHA256 over ordered full input records and matching policy, with private 32-byte key and constant-time verification | HMAC binds the source snapshot, **not** who edited review instructions |
| Private review file safety | Review keys and manifests require regular files, strict permissions and matching identity, size, ownership and timestamps before and after reading. Keys use a fixed 32-byte buffer; manifests use a bounded 4 MiB read. Failed new-key writes/syncs attempt inode-checked cleanup without removing a replaced file. Synthetic read mutation, path replacement, oversize and failed-initialization tests passed. | These checks are not an atomic snapshot against a hostile same-user process, and do not guarantee secret zeroization or power-loss atomicity. Use stable, private review files. |
| Browser provenance integrity | Passflick's browser labels are bound to actual original CSV source positions, not merely user-controlled `migration.*` fields in existing Bitwarden JSON | Vaultwarden-only accounts intentionally cannot enter browser-attributed Passflick snapshots |
| Linux process core-dump mitigation | `src/process_safety.rs` calls Linux `prctl(PR_SET_DUMPABLE, 0)` at CLI startup, verifies `PR_GET_DUMPABLE == 0` before reading credentials and fails closed if the kernel rejects the setting; an isolated unit regression passed strict CI. | Does not zeroize Rust allocations, encrypt swap, remove backups or prevent privileged memory inspection. Other processes, past dumps, and filesystem copies are outside this guard. |
| Input and format bounds | Individual source inputs are capped at 64 MiB, the combined JSON/CSV batch at 256 MiB, browser source count at 32; review manifests, Passflick CSV, item counts and static Vaultwarden format sizes are also bounded | Parsing large nested metadata may still use substantially more memory than file size |
| Tracked-file privacy | `ci/release-privacy.sh` fails when source control tracks common credential-export, database, private-key, archive or backup file extensions | Filename checks **do not scan Git history or detect secret-like literals embedded in source text** |
| Isolated consumer acceptance | Real Vaultwarden import/export, duplicate-import detection, reversible Trash rollback and real Passflick CLI browser-snapshot import using synthetic disposable vaults | Not a real target-host deployment or proof that all future client/server versions behave identically |

## Open security work

1. **Multi-output failure semantics:** earlier verified companions are removed on ordinary subsequent failures only when their inode identities match. A newly hard-linked output is likewise removed on a late write/sync failure only if it still points to the staged inode. Synthetic replaced/vanished companion tests, late hard-link failure cleanup, and forced-replacement backup retention passed [strict CI run 41489697965](https://github.com/sguzman/bw-password-dedup/actions/runs/41489697965). **Independent pathnames remain nontransactional.** New post-write and final-bundle SHA-256 checks catch ordinary content tampering, truncation, and unsafe permissions while the process is running, with inode-checked cleanup on failure; they do **not** protect an interrupted export after a kill or power failure. A private, fsynced write-ahead marker now flags ordinary failures and an interrupted process before final verification; a subsequent run refuses to overwrite an existing marker. Never import or retry after ambiguous termination without inspecting every expected destination, marker and backup. This marker is not a positive receipt proving post-crash completion, nor a substitute for an atomic multi-file transaction.
2. **Untrusted directories and filesystem races:** the JSON/CSV and private review readers check opened-file identity, and the review key/manifest reader now also checks final descriptor/pathname identity, timestamps, ownership and size after bounded reads. `src/path_safety.rs` now refuses an output parent or ancestor that another unprivileged account can replace, rejects explicit symlinked directory components, and preserves private subdirectories under trusted sticky-bit parents such as `/tmp`. Synthetic CLI checks fail before producing export files or review keys. The writer rechecks the output parent at publication; source, review and forced-backup opens now use Linux no-follow/nonblocking flags to reject last-component symlink and FIFO substitutions even before metadata verification. **Residual:** a process with the same user's privileges, a privileged directory writer, nonstandard filesystem behavior, or races between verification and rename can still change pathnames. Use private, quiescent input and output directories; these checks do not provide a kernel-atomic snapshot.
3. **Memory and crash handling:** `prctl(PR_SET_DUMPABLE, 0)` now disables ordinary Linux core dumps before the CLI reads credentials and is verified via `PR_GET_DUMPABLE`; the call fails closed if unsupported. This reduces one crash-exposure path, **not** all secret retention. Credentials are still materialized as `serde_json::Value` and temporary buffers, without a general zeroization guarantee; swap, privileged inspection, shell history, old dumps, and backup/sync copies remain outside this process setting.
4. **Untrusted files and resource exhaustion:** each file is limited to 64 MiB and combined source files to 256 MiB; at most 32 browser CSV inputs are accepted. A sparse-file regression verifies the cumulative cap before parsing. Very deeply nested metadata or copies created during conservative reconciliation can still multiply resident memory beyond input size, so no strict process-memory ceiling is claimed.
5. **Licensing and distribution:** no approved project license or source release authorization has been recorded. External Passflick, the MIT test helper and GPL Bitwarden CLI are test-time tools and must not be silently bundled into a public binary.
6. **Host acceptance:** the exact EndeavourOS/fish target-host smoke test and restoration from an existing local Vaultwarden backup have not been executed. No real credentials should be processed until owner acceptance.
