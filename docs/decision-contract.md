# M5 authenticated decision contract

**Implemented and tested synthetically on Linux.** The local Rust CLI now supports snapshot-bound, explicit conflict decisions using a private HMAC-SHA256 key. It does not modify original exports or password-manager stores. The complete user workflow is in [review-workflow.md](review-workflow.md).

## Binding and review material

An executable manifest is generated by `--bound-review-template` with `--review-key`, using a private random 32-byte key initialized by `--init-review-key`. The HMAC binds:
- Complete ordered canonical source records, including sensitive values (only in memory during calculation)
- Original Bitwarden export metadata, including folders and unknown root data
- Input file identity and ordered browser source specifications
- Effective matching and normalization policy
- Explicit compatible URI and compatible-field merge options

The manifest includes only the HMAC, schema metadata, fixed conflict flags and safe input-relative references, never the raw secret-bearing HMAC input. HMAC verification uses the cryptographic library's constant-time verifier. The key is held in a separate `0600` file, and must remain private. A changed key or modified snapshot invalidates replay.

The user may edit the decision actions in the protected manifest. The HMAC authenticates the source snapshot, **not the user's edits or the identity of the manifest editor**. The tool must not accept untrusted manifests.

## Allowed actions

- `defer`: preserve alternatives without choosing.
- `keep-both`: explicitly preserve all alternatives.
- `choose-one`: require a selected source position belonging to the exact verified group. All other candidates remain in the original input files and are recorded as user-excluded in the redacted reconciliation ledger.
- `merge-nonsecret`: combine only provably compatible nonsecret metadata and exact shared secrets; refuse any incompatible password/TOTP, URI match metadata, ownership, title, or unrecognized field.

If an earlier automatic merge makes a selection ambiguous, the program fails closed. Unknown actions and fields, group modification, duplicate/out-of-range references and contradictory choices fail without writing output.

## Deterministic replay and recovery

The same ordered sources, config and decisions produce identical cleaned JSON. Changing source order, one password, one TOTP value, the matching policy, key or manifest schema prevents replay. The result's reconciliation accounts for each original source position exactly once: retained, merged or explicitly excluded. No original exports are mutated, and files cannot be overwritten silently.

The tool checks review manifest permissions, rejects input/output aliasing, and uses private output modes. Do not upload real exports, review keys or manifests to public CI or support chats.

## Evidence and remaining limitations

The implementation passed 55 Rust unit tests and 25 CLI integration tests with strict rustfmt, Clippy and compilation at [GitHub Actions run 41377484346](https://github.com/sguzman/bw-password-dedup/actions/runs/41377484346). This satisfies M5's *synthetic* acceptance criteria; it is **not** an independent production security audit.

M6–M8 remain open. In particular, the app still needs isolated Vaultwarden import/round-trip and Passflick snapshot-consumption tests, plus adversarial security QA, packaging and recovery documentation. Review manifests are mutable local user instructions, not cryptographically signed approvals; prevent untrusted access to them. No real user credentials should be processed until those gates pass.
